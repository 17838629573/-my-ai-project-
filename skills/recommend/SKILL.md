# 项目推荐

当用户说"帮我做XXX"但没明确方案时，先搜网上有没有成熟方案可复用/参考。

## 流程

### 1. 理解需求
从步骤0 pre-step 上下文和用户原始 query 中提取：
- 项目类型（Web App / CLI 工具 / 库 / 框架 / 游戏 / 数据分析 / …）
- 技术栈偏好（如果有提及）
- 核心功能（3-5 个关键词）
- 用户水平（小白 / 有经验 / 专家——从语气判断，不问）

### 2. 搜网上的成熟项目
用以下关键词组合搜索：
- `{核心功能词} {项目类型} {技术栈} github`
- `{核心功能词} {项目类型} 开源 推荐`
- `best {核心功能词} {项目类型} 2026`

至少搜 2-3 轮，覆盖不同关键词角度。禁用只搜一轮就下结论。

### 3. 筛选标准（按优先级排序）
按以下维度筛选 Top 3-5 个项目推荐：

| 优先级 | 维度 | 数据来源 |
|--------|------|---------|
| ⭐1 | **社区认可度** | GitHub Stars、Forks、Issue/PR 活跃度 |
| ⭐2 | **维护状态** | 最近更新时间、版本发布频率、CI 绿色 |
| ⭐3 | **文档质量** | README 完整度、API 文档、示例代码 |
| ⭐4 | **依赖风险** | 轻依赖 / 大而全 / 已停止维护 |
| ⭐5 | **用户评价** | 技术社区讨论热度、StackOverflow 引用 |

### 4. 输出推荐清单
按推荐度排序，每个项目一张卡片：

```
## 推荐 1：[项目名]
- **仓库**：[GitHub URL]
- **⭐ Stars**：[数字]
- **最近更新**：[日期]
- **一句话**：什么项目、解决什么
- **优势**：为什么推荐这个（2-3 点）
- **劣势**：可能的问题（1-2 点）
- **适合你吗**：判断依据
```

### 5. 问用户
输出推荐清单后，给出选项：
> **方案A**：选一个推荐项目 → 后续基于该项目迭代/集成
> **方案B**：都不满意，从零做 → 跳过推荐，走步骤 1→7
> **方案C**：换关键词再搜一轮

用户选择后：
- A → 记录选择的项目名称 + URL 到 WORKLOG（`{时间} | 步骤0 | 推荐方案: {项目名}({URL})`），然后步骤1 接需求时以此项目为起点
- B → 记录`{时间} | 步骤0 | 从零做`，跳过推荐
- C → 回步骤 2 换关键词重新搜

## 约束
- 必须基于搜索结果推荐，不能编造项目信息
- 搜不到合适项目时如实说"未找到高匹配度项目"，给出方案B和C
- GitHub Stars 数如果不是最新可注明"数据可能有滞后"
- 不要强行推荐不相关的项目
