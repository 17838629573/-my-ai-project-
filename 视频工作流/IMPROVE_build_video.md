# build_video.py 改进措施（改这块前必读）

## 已修
1. `frame_index` 返回 `(i0,i1,f)` 三元组，取 `[0]`；`frame_durations` 不存在，均匀时长自行构造。
2. 逐帧居中对齐：统一包围框 + 每帧按自身 bbox 中心平移到框中心（pivot 锁定），
   消除跨帧漂移导致的横向抖动（实测人漂移 269px）。

## 未修（根本缺陷，优先级高）
**A. 骨架绘制把整条链画成绕原点旋转的曲线**
实测骨架宽高比：旗 0.69→1.27、玄奘 0.71→1.55，中心 x 漂移 92→115。
真实物体应是「主体竖直（重力方向）+ 横向小幅摆动偏移」，
现在是整条链在空间中大幅旋转 → 生成图形态随相位大幅变化 → 帧间一致性差。
修法：骨架绘制分离「主体姿态（固定竖直）」与「摆动偏移（沿风向，幅度=物理振幅）」。

**B. 三人共用一套序列帧**
慧琳、石槃陀直接复用玄奘图集，仅相位错开 0.13s，服饰/体型无差异。
业界解法：Modular Atlas（body base + 服饰 overlay 分层合成）或换色图生图。

**C. solver 输出异常**
四物体 regime 全为 chain（含人物）；`lift=49.2°` 对所有物体相同（由 U 算，
对 gait 驱动的人物无意义）；`末端峰峰=0.000m`（chain 的 tip_pp 未算出）。

**D. 生图不按指定品红出**
旗 (219,49,128)、玄奘 (185,50,100) 玫红。已用 `chroma_key(ref=None)` 自动取四角色抠像
（前景占比 旗19.8% / 人14.8%）。下次主体偏红时应改指定绿色背板。

## 验证口径
成片体检用「与背景差分 + 阈值 120」：mp4v 有损压缩会引入全画面噪声，阈值 40 会误判。

**背景**：`assets_tang/`（73M）与 `_生成/`（45M）已清空，目的是让每次成片的所有图
都按当前参数生成，不混入旧参数产物。清空后出片链路必须先补齐素材。

带着 None 往下走，最终崩溃信息完全指不到"缺素材"这个真因。

**已落地的拦截**：

- 树缺图 → 非致命，但**必须打印明示**，禁静默跳过
