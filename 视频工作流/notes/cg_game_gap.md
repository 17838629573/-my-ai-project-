# 对照 CG / 游戏行业，我们还缺什么（代码合成路线）

## 零、一个重新定性：方块人其实是 previz

Mass Effect 3 的 cinematics 管线（BioWare，业界最成熟之一）：

```
1 剧本 → 2 故事板 → 3 previz animatics（灰盒空间 + 静态占位角色 + 临时音轨）
  → 4 narrative playable（拼起来验证节奏/机位/剪辑点）
  → 5 检查叙事密度/节奏 → 6 动画与动捕 → 7 配音 → 8 灯光 → 9 VFX + 音频
```

**我们的"方块人渲染"正好落在第 3-4 步**，是合法阶段。
问题不是"用了方块人"，是**我把 previz 当成了最终交付**。

行业在这里会 lock 节奏和剪辑点，然后才上精细资产。
我们缺的是：previz 阶段没有"锁定"动作，直接跳到了出片。

## 一、缺 Z-depth（这是穿模的根因）

CG 合成标准 AOV 分层（Redshift/Cycles 实测管线，12+ 层）：

```
beauty / diffuse / specular / reflection / shadow / emission
GI / AO / cryptomatte / Z-depth / motion vector / normal / position
```

我们只有 **beauty 一层**。

最该补的是 **Z-depth**：
- 深度排序（防穿模）—— 现在是靠 slot 索引猜
- 景深（camera defocus）
- 雾/大气衰减（沙漠镜头需要）
- 选择性调色

`contact_shadow` 我们有，但那是接触阴影，不等于深度层。

## 二、缺柔性蒙皮权重

Spine 两种绑定：
- **刚性绑定**：一个附件只受一根骨骼影响（父骨）—— 我们现在就是
- **柔性网格蒙皮**：顶点可受多根骨骼影响，权重可绘制

后果：抬手臂时肩部不会自然拉伸，会"生硬地撕裂"。
这正是刚性绑定的已知缺陷，业界用权重绘制解决。

我们骨骼只有 8 根且无膝踝，柔性蒙皮短期内做不了，
但**这解释了为什么我们的动作会显得贴图感重**。

## 三、缺色彩管理

CG 管线统一走 **ACEScg + 线性空间 + 32bit EXR**，合成在线性空间做。
我们全程 uint8 sRGB 直算，alpha 混合也是 sRGB 空间。

后果：半透明叠加、淡入淡出、接触阴影的过渡会偏。
字幕淡入固定 6 帧，如果在线性空间算会更自然。

## 四、缺 previz 的"锁定"动作

行业在 previz 之后会 lock：pacing / camera / edit cut。
**锁定后才进入精细资产。**

我们 skip 了这一步 —— 方块人验证完节奏后没锁定，也没回头替换。

## 五、我们不缺的（别被带偏）

- **景别/构图精确可控** —— 图生视频做不到，这是我们的优势，保留
- **按需调度** —— 已有 loop_engine
- **走路锁相** —— 已有，且按文献校准过

## 六、优先级建议

| 优先级 | 缺什么 | 收益 |
|---|---|---|
| 高 | Z-depth 层 | 根治穿模 + 雾效 + 景深 |
| 高 | previz 锁定流程 | 防止 previz 当交付 |
| 中 | 线性空间合成 | 半透明/淡入更自然 |
| 低 | 柔性蒙皮 | 需先补膝踝骨 |
