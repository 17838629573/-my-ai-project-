# NPC 环境动画 / 配角固定逻辑（行业调研）

## 一、分层：不是所有 NPC 都给完整 AI

UE5 Mass AI / strayspark 四层：

| 层 | 内容 | 成本 |
|---|---|---|
| L1 静态放置 | 座位观众、固定岗哨、摊位 | **零模拟开销** |
| L2 背景人群 | 实例化、中远景、共享动画 | 极低 |
| L3 前景人群 | 全骨骼、避让 | 高（数十个） |
| L4 玩法 NPC | 行为树、完整物理 | 高（10-30个） |

关键：**用 L1 把环境填满，动态人群只是补充**。

## 二、共享动画池 + 相位错开（最省的一招）

Pose Sharing：多个 NPC 共享同一段动画实例，**只错开起始时间**。
原文例子：一千个观众鼓掌，系统只维护一段掌声动画，各人从不同时间点开始播。

UE5 VAT（Vertex Animation Texture）：动画烘进纹理，GPU 按实例 ID + 时间采样。
0.002ms/agent vs 标准骨骼 0.1ms/agent —— 差 50 倍。
代价：只能播预烘焙动画，不能做 IK/动态混合。远景完全可接受。

## 三、Idle 池设计（MoCap Online）

- 每个角色原型 **5-8 个 idle 变体**
- 长 ambient 30-90s（行为更丰富）／短 idle 2-4s（易混合但循环可见）→ 混用
- **必须 clean loop**（末帧≈首帧）
- 微动作收益最高：头部转动、重心转移、呼吸调整、手臂微调
- 按角色职能分段 idle 池，不要一套通用

**产出多样性的三招**（关键）：
1. 起始时间随机化
2. 播放速率微调
3. idle break 随机计时器（5-30s 触发一次偏离动作，回到 idle）

## 四、巡逻 FSM（野怪/小兵）

状态：Idle → Patrol → Chase → Attack → (丢失) Return
- 路径点循环：`idx = (idx+1) % len`
- 到点减速：velocity × 0.3，防止过冲、转角更自然
- 丢失玩家后回"最后已知位置"停留，再归队（不要瞬移回巡逻点）

## 五、动画 LOD

远景 NPC 15fps / 中景 30fps / 近景 60fps。
实测可降 CPU 50%。

## 六、对照我们的现状

已有 `tier_target_h(body_frac)`：按占屏分级资产高度
—— 这其实就是业界的"按屏幕占比做 LOD"，方向一致。

讲经听众属于 **L1 静态 + 轻微 ambient**：坐姿、无位移，
只需 idle + 微动作（呼吸/偶尔转头），不需要巡逻 FSM。

可复用：
- 共享 idle 池 + 相位错开（同一张图多个实例，错开动画相位）
- idle break 随机计时器
- 按景别降帧（远景听众可 15fps 更新）
