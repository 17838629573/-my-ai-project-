## 真坑（踩过，别重犯）

### 坑1：横向 / 深度 px_per_m 是两个不同公式，混用会错 6 倍
```
横向 px_per_m = (y - v_h) / h
深度 px_per_m = (y - v_h)^2 / (f * h)
```
Mode 7 原文：每扫描线缩放 z(sy)=h/(sy-s_horizon)（横向），其梯度 dz/dsy=-h/(sy-s_h)^2（深度）。
实测比值非常数：y=878 时 3.39，y=557 时 17.82。
**旧代码全程用横向公式算纯深度方向的路径推进 → 错 6.1 倍，人越走越远越"狂奔"。**

### 坑2：像素弧长 ≠ 世界弧长（这是"人物飘天"的数学来源）
路径 6 段世界长度【每段都是 8.10m 等距】，但像素长度 238→17px（递减 14 倍）。
旧代码 `s = speed * px_per_m * t` 按像素匀速推进 → 世界速度实测 1.5→54.76 m/s 失控。
t=2.6s 时脚 y 冲到 561.3（逼近地平线 482），观感就是"飞上天"。

### 坑3：三种判据我误报过三次，别再犯
- 平行屏幕路径：用 ΔZ 衡量速度 → 横向走 ΔZ=0 → 误报"100%失控"。**必须用地面总位移 hypot(ΔX,ΔZ)**
- 折返路径：速度出现 -1.491 是【正确行为】，不是 199% 失控
- 蜿蜒路径：跨折线段时用两点直线距离量 → 弦长<折线弧长 → 误报 8.62%。
  细分 1→5→20→60 倍误差恒定 9.63% 不动，证明是测量假象不是离散化误差

### 坑4：地平线有两个值，代码用了错的那个
spec 声明 482（在 path.perspective 下）、groundline 独立检测 479（吻合）、
_surface 算出 588.5（错：它读顶层 spec.get("horizon_y") 取到 None 后回落 Hough 消失点误检）。
几何自检一锤定音：v_h=482 时 z=+60m（合理）；v_h=588.5 时 z=-107m（相机背后，不可能）。

## 依据
- Frenet-Serret 弧长参数化 s(t)=∫|γ'(τ)|dτ，以 s 为参数时 |dγ/ds|=1（几何与速度彻底剥离）
- pinhole 地面平面反投影 Z=f·h/(y-v_h)、X=(x-v_x)·Z/f
- 项目铁律：地平线以上不可能是可行走面（Footprints CVPR2020）
