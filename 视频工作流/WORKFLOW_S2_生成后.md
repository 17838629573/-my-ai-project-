## 八、帧率基准（framerate.py，铁律28/29/30）

```
FPS = 60     ← 全局唯一，输出帧率定死 60
```

| 铁律 | 内容 | 实测 |
|---|---|---|
| **28** | 帧率单一数据源，禁第二常量（`W,H,FPS=...60` 也算） | 抓出 `systems.py:L178 WALK_FPS=24`（死常量，零引用） |
| **29** | 序列帧数 `N=round(T_phys×FPS)`，禁手填 | 幡旗 T=0.585s → **35 帧**，不是 24 |
| **30** | 素材帧数不符 → 播放速率钳制 ±15%，超出即报错 | 24帧 vs 35帧 → 0.686，被拒 |

### 修掉的"制造帧数"
```
物理周期 T=0.585s (f=1.708Hz，由 St 算出)
旧：24 帧 @60fps 每帧播1张 → 一圈 0.400s → 实际 2.500Hz
    → 比物理快 46.4%     ← 帧数反过来决定了频率
新：N = round(0.585×60) = 35 帧，且不符即报错
```

### 修掉的 dt 写死
```
systems.update_physics: dt = 1.0/60.0  （写死）
loop_engine:            t = i / fps    （可传 24/30/60）
→ 24fps 输出时错位 2.5 倍、30fps 错位 2.0 倍
现：dt = 1.0/ctx.fps
```
