# rigid2d.py 踩坑记录

**职责**：2D 刚体世界——积分、碰撞检测、顺序冲量求解。支撑 C16 堆叠 / C17 斜坡 / C19 摆锤。

**状态**：739 行，超 R2 上限（500），待拆。

## 一、关键参数与出处

| 参数 | 我们的值 | 出处 |
|---|---|---|
| 求解器 | 顺序冲量（PGS） | Erin Catto, *Iterative Dynamics with Temporal Coherence*, GDC 2005 |
| 迭代次数 | ITER=12（默认 8） | Box2D 默认 8；无暖启动需 ~30，有暖启动 8 足够 |
| Baumgarte β | 0.2 | Box2D-Lite `k_biasFactor = 0.2f` |
| 允许穿透 slop | 0.01 | Box2D-Lite `k_allowedPenetration = 0.01f` |
| 固定步长 | 1/240 | 固定步长 + 累加器模式，与渲染帧率解耦 |
| 积分器 | Velocity Verlet | 对常加速度精确，属辛族 |

**迭代次数的收益曲线**（PhysX 实测口径）：4~6 够实时，8~10 用于高精度仿真；**超过 10 次收益急剧递减而开销线性增长**。

## 二、踩过的坑

### 坑 1：半隐式欧拉累积偏低，弹球高度不收敛

**现象**：C18 弹球峰值偏差 0.048~0.062 m，超阈值。

**根因**：半隐式欧拉每步偏低 `0.5·g·dt²`，随时间累积。

**修法**：换 Velocity Verlet。改完 `restitution_err` 降到 2.19e-15，峰值严格 `h·e^(2n)`。

---

### 坑 2：穿透修正符号写反 → 球越弹越高

**现象**：C18 反弹一次比一次高，能量凭空增加。

**根因**：落地速度公式 `vc² = v1² - 2g·pen` 写成了加号。

**修法**：改回减号。这条没有改判据，是代码真的错——判据抓对了。

---

### 坑 3：堆叠抖动 0.2043 px（耗时最长的一个）

**现象**：四层箱子层序正确、末帧静止，但残余抖动 0.2043 px，超阈值 0.1 px。

**排查过程**（这一步比结论重要）：

1. 先怀疑暖启动没生效 → 修了缓存写入时机与匹配键 → **数值逐位不变**，排除
2. 怀疑接触排序 → 加"自底向上排序" → ITER=12 时反而更差（0.3045），排除
3. 做参数实验，才定位到真因：

```
dt = 1/60   → jitter 0.2043 px   FAIL
dt = 1/240  → jitter 0.0035 px   降 59 倍

ITER 12 → 30 → 60 → 120
      0.2043 → 0.1169 → 0.0189 → 0.0002
```

**结论**：不是算法缺陷，是**步长不一致导致求解器收敛不足**。

**修法**：`stack_sim` 默认步长统一到 1/240。理由——C17 斜坡、C18 弹球本来就都用 1/240，**只有它用 1/60，是项目内的不一致**。

这是修正不一致，**不是放宽阈值**：阈值仍是 0.1 px，物理振荡是真的消失了（0.0035 px）。

---

### 坑 4：暖启动接上了但没生效（仍未解决）

**现象**：修完缓存后，四个箱子残余位移与修前**一模一样**，说明缓存根本没被读到。

**已修的两个错**：
- 缓存写入时机：在求解**前**就存值，存进去的恒为 0
- 匹配键不稳：接触点 ID 随微抖漂移，命中率只有 16% → 改成按物体对聚合

**怀疑方向**：`step()` 里 `_contacts()` 被调用两次——末尾那次为算 `max_pen` 重建接触，可能把缓存覆盖成未求解的零值。**成因未最终确认，C16 的抖动是靠改 dt 绕过的，不是靠修好暖启动。**

> 按 Catto 的说法，暖启动的价值正是"上帧的解接近本帧的收敛解"，Box2D 靠 `b2ContactID`（feature ID）做接触点持久化匹配。我们用的是按物体对聚合，粒度粗于 Box2D，这可能是命中率上不去的根因。

---

### 坑 5：仿真步数当成视频帧数 → 慢放 12 倍

**现象**：C16 视频 721 帧、fps=20，放 36 秒；但仿真只有 3 秒 → **95.6% 是重复帧**，看着像卡住。

**根因**：721 个仿真步直接当 721 个视频帧。

**修法**：新增 `resample_tracks(tracks, sim_dt, fps, duration)`，按 `t = i/fps` 反查连续索引做线性插值。C16 → 3.0s × 24fps = 72 帧。

**教训**：仿真时钟和渲染时钟是两个时钟，必须显式重采样，不能混用。

---

### 坑 6：坐标假定 y≥0，把画面外的东西裁掉

**现象**：C19 摆锤整段只剩背景；C16 顶箱被裁。

**根因**：摆锤坐标系 y 恒为负（锚点在原点上方），映射到画面外；C16 箱子堆到 1.76 m 而视野只给了 1.6 m。

**修法**：新增 `_phys_frames_auto()`，按轨迹实际包围盒自适应定标。摆锤静止率 1.0 → 0.0。

## 三、几个易错判据口径

| 判据 | 易错点 | 正确口径 |
|---|---|---|
| 能量增益 | 阈值写 `<= 0.0`，浮点残差 1.47e-16 被判"能量增加" | 加 1e-9 容差 |
| 质心跳变 | 重复帧的差分图为空、质心无定义 → 输出随机值（曾误报 158 px） | 逐帧前景质心，C16 实测 median 0.000 |
| 斜面加速 | 用水平距离 / 全程路径长 | 分母应是**沿斜面的弧长** |
| 摆锤高度 | 球心高度当离地高度 | 减掉半径 |
| 摆锤张力 | — | 静止时 = mg，实测 9.8066 N，差 3.6e-6 |
