# 判定铁律（不可覆盖）

出处：业主提出并裁定（2026-10 项目内审定）；机制落地依据 import-linter
`ignore_imports` 显式登记法（只减不增）+ PIT 变异测试的"可证伪"原则。

## 铁律一：假阳性必须附最小复现

> 任何被判定为"假阳性"的报错，**必须附一个最小复现**——能证明这条报错在
> **正确配置下不会触发**。做不到复现的，**一律按真问题处理**。

最小复现 = 一段可执行脚本，做到两件事：

1. **正向**：按当前（错误）配置运行 → 该报错**重现**
2. **反向**：按正确配置运行 → 该报错**消失**

只做正向不做反向 = 没证明它是假阳性，只证明了它会报。

### 落地

- 工具：`tools/repro.py`（R17 豁免验证）
- 登记册：`tools/suppress.json`，每条豁免含 `id / rule / repro / 声明现象 / 归属 / 复核日期`
- 命令：`python3 -m tools.repro` 全量验证；`--add ID` 添加
- 判定：实测 == 声明 → PASS；否则 FAIL → **按真问题处理**

## 铁律二：判定靠命令输出

不运行就不算数。`import` 成功 ≠ 功能正确（拆分 `run_all.py` 时，`from x import *`
不下划线名导出，import 全绿但 A 组必然 `NameError`——只有实跑才暴露）。

## 铁律三：缺能力不静默降级

用例缺能力必须抛错并标记 STUB，**不得**复用其他用例函数充数
（`F35` 曾复用 `case_A1` 只跑 48 帧却报 PASS，属降级造假）。

## 铁律四：阈值要有出处，且设计值与红线分开

不允许"实测贴着阈值过"（如 459.6 vs 阈值 460，裕度 0.1%）。
设计值留余量，红线单独设。新能力开工前先搜证（工具优先，禁凭记忆）。

## 铁律五：债务显式登记，只减不增

已知问题进 DEBT 清单，带归属与复核日期。清单外一律照报。
**禁止**为了让工具体检"全绿"而改工具让它闭嘴。
