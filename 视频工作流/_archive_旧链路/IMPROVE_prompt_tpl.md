## 三、踩过的坑（按发生顺序）

### 坑1：扫描器 split 标记法自指污染（第7次）
```python
_logic_src() 函数体自含 "# BEGIN EXAMPLES" 字面量
→ split 把它当第二标记 → 只取到 497 字符空壳 → 自检假 PASS
```
**修法**：改用 AST `_scan_targets()`，取 TPL 赋值节点 + 函数/类体，
显式跳过 `_logic_src / _scan / _scan_targets / self_check / EXAMPLES / HARDCODE_BAN`。

**教训**：任何"用字符串标记切代码再扫描"的写法都会被扫描函数自身污染，
**一律改 AST**。

### 坑2：driver.py 扫描器同样空转
```python
_scan_hardcode(src) 取 split(BEGIN)[0] → 逻辑区一行没扫 → 假 PASS
```
已同样改 AST，目标区 len=4272 含 FAMILIES，并加双证伪
（"扫描器有效"+"目标区覆盖"）防空转。

**教训**：**只抛错不算防御**。注入假实现（补一个 biped）就能绕过单点校验，
必须加第二层"字段必须真实存在"。

### 坑3：证伪项要验"扫描器本身有效"
首轮自检 10/11，FAIL 的正是证伪项——它发现扫描器只扫 497 字符。
**证伪项救了这次**。以后每个扫描器都必须配：
1. 扫描器有效（能命中故意埋的词）
2. 目标区覆盖（len 足够大，含关键结构）
