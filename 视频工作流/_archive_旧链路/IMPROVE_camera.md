# IMPROVE_camera：镜头意图→机位求解

## 因果倒置 bug（本轮最严重）
旧链路：`生背景图 → 从图反推 h_cam → 算落点`
反推出的 h_cam=3.366m 只能描述**一个平面**，装不下"墙顶 12m 马道 + 地面"，
于是树悬空、旗落地。**根因不是锚点代码写错，是根本没做过机位设计。**

正解链路：`叙事意图 → 解机位(7自由度) → 透视(正推) → 落点 → 用机位指导生图`

## 业界依据
- **LensCraft 2025**：景别+角度 → 球面坐标 → 相机位置。scale ELS3.0/LS1.5/FS1.0/MCU0.7/ECU0.5
- **针孔模型**：`rho = f_px·h_subject/(tau·H)`；地平线 `v_h = H/2 − f_px·tan(pitch)`
- 景别定死 → 距离唯一；角度定死 → 相机高唯一。**数字部分代码全算，只有叙事需人/AI 拍板**

## 已定口径
- 景别表 tau：ELS 0.22 / LS 0.40 / FS 0.60 / MCU 0.80 / ECU 1.00（tau=1/scale）
- 角度表（相机高/主体高）：low -0.25 / eye 0.50 / high 1.30 / bird 3.00
- 相机在主体前方 rho 处，x 对齐主体
- 相机系：forward=(0,−sin p, cos p)，pitch>0 俯视

## 实测（僧人 1.7m 在 12m 墙顶 z=40，柳树 6m 地面 z=35）
```
solve_coappear 自动解出 ELS/low  h=11.57m  pitch=-4.0°  v_h=559.8  tau_eff=0.044
  僧人 底v=549 顶v=507  可见
  柳树 底v=890 顶v=717  可见
墙顶(12m@z=40) y=547.5   地面(z=35) y=940.8
```
**A/B/C 机位选择是伪问题** —— 声明"远景+共现"后代码自己解出，不需人选。

## 关键新发现：可放置深度区间
```
地面   可放置 z ∈ [33.3, 400] m
墙顶   可放置 z ∈ [0.0, 400] m
```
**地面 z=25 在画面外（y=1093 > 960）—— 这就是旧版树悬空/消失的真因。**
物体深度不是随便填的，机位一定，区间就定了。

## 踩坑
1. 证伪构造错：以为"极远树 z=5 永不可见"，但退远能救任何有限深度物体。
   改用 `max_scale=1.0`（禁退远）才构造出真无解 —— 且验证了"放宽后可解"。
2. `_project_y` 未定义：直接复用 `_perspective.y_at_depth`，
   高度平面 == 相机相对高 `(h_cam − y_base_m)` 的地面，不重造公式。
