# IMPROVE_sheet_plan — 图集规划详解层

契约 `contracts/sheet_plan.md` 只留铁律条目与接口；

## 铁律54 业界依据（视频不封顶 16 帧）

| 来源 | 要点 |
|---|---|
| Singular.live | 8×8=64 格 @30fps，16×16=256 格 @60fps —— 视频高帧率本就多格 |
| SpritePilot | 10–12fps 是**游戏**足够值，不是视频值 |
| 团结引擎 | `MAX_MAT_FRAMES=16`（4×4）是游戏定式，被误当成视频天花板 |

历史 bug（真实发生过）：
```
N=35 → mat_frames = min(35, 16) = 16 → playrate = 35/16 = 2.19
```
= 27fps 素材硬撑 60fps，每格撑 2.19 帧，必然顿。
根因：把团结引擎 4×4 游戏定式当成了视频上限。

## 铁律55 业界依据（多帧必须合图）

| 来源 | 要点 |
|---|---|
| 团结引擎 | 「上传角色参考图能显著减少帧间外观漂移」 |
| FrameSprite | 一致性来自「减少模型每帧要重新决定的东西」 |
| Sorceress | 参考图 + 锁定 seed，12 帧不漂移 |

**逐帧单图 = 每帧都让模型从零决定一次构图** —— 这是帧间漂移的结构性来源。

## 铁律56（格数上限是模型能力，不是代码常量）

默认 `max_cells=16`（4×4），依据 GPT-Image「先 8 帧验稳定再扩 16」。
AI 可依据所用生图模型上调（如 25/36）——**上限由模型声明，代码不硬编码**。

超过上限 → 拆成多张图集，所有图集共用同一张身份参考图。

## 铁律57（长条物体走 strip）

lobehub sprite-forge 原文：platforms / floors / walls / gates / doors /
long hazards 「use one-by-one, 1×3/1×4 strips, custom wide cells」。

幡旗、长枪、树枝等长宽比 > 2 的物体必须走 strip（1 行 N 列）。
用 4×4 方形格 → 每格大量留白，主体被压小（早期幡旗被压成 105×52 糊掉）。

## 历史踩坑

1. **长条物体塞方形格**：幡旗 aspect=3.0 塞 4×4 → 主体被压到 105×52，糊。
   解法：走 strip，宽格 512×256。
2. **格间 padding 缺失致接缝**：padding=0 时相邻格像素互相渗。
   固定 padding=2。
3. **单张 sheet 超 2048**：降 cell_px 而不是硬超上限。
