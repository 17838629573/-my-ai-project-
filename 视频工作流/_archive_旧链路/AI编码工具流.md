从真实项目反推。每条规则对应一次真实翻车，不是设计出来的。

## 一、核心：契约 + 门禁 + 证据

| 机制 | 管什么 |
|---|---|
| **契约块** | 改代码时的读取量（改 systems 只读 568 字契约，省 93%） |
| **门禁** | 拦住"跑不起来 / 静默失效"的代码 |
| **notes/** | 改动史，不进常驻上下文 |

**契约是给我读的，门禁是拦我的。** 只有契约没有门禁 = 只有说明书没有护栏，
我必然偷懒（用色块顶真实资产就是这么发生的）。

## 二、十二条铁律（按翻车次数排序）

### 1. 判定靠命令输出
翻车 3 次：字幕从未绘制 / LPC 尺子本身歪 / 摆臂骨骼不存在却报"已生效"。
**凡无命令输出的结论，一律视为未验证。**

### 2. 证据必须能证伪（v3 新增 · 本轮最重要教训）
我用"右半区帧间差 29.88"证明旗在动 —— **假证据**。
该镜头是运动镜头，背景视差滚动本身就会让右半区变化，
这个指标区分不了"旗在动"和"背景在动"。

→ **合格证据必须是开关对照**：`有X vs 无X`、`A帧 vs B帧（同场景）`。
   不能用一个"看起来在变化"的聚合指标充当证据。

### 3. 落盘才发生
我 present 过三个根本不存在的路径。
→ 声称落盘前必须 `ls` 验证。

### 4. 逻辑唯一，差异在数值表
实测重复：力公式 12 处、面积 10 处、px_per_m 9 处。
→ 新增物体 = 加一行数值，不动代码（业界实测：物理 bug −40%）。

### 5. 模型填物性，代码算派生
手填 `k=4.4` → 面积误差 6.8%（实测反推 4.12）。
→ 物性可搜（AI 填），结果与派生量由代码算，禁 AI 直接填。

### 6. 用对物理模型，别用魔法系数（v3 新增）
我用 `acc = F/m` 再乘魔法系数 `0.004` 当旗的位移 —— 物理上不成立。
旗是**悬臂摆**，位移由**摆角**决定：`theta = atan(F/(m*g))`，
`位移 = L·sin(theta)·r`，根部 r=0 恒为 0。
而 `physics.py` 里明明已有 `torque()`，我却没用。

→ **先确定模型族（周期/点到点/摆动/被动物理），再取参数。**
   出现"乘个系数调一调"就是模型选错的信号。

### 7. 禁静默跳过
系统显示"启用"、耗时也统计、但不报错 —— 实际没接。
→ 缺失必须报错，降级要显式声明。

### 8. 硬阻断，不给后门
`missing_assets()` 被我设计成"告警不阻断" → 18 项缺口用色块顶了十几轮。

### 9. 门禁必须能拦住"跑不起来"
deps.md 声明了、validate PASS，但文件没写 import → `NameError`。
→ **validate 通过 ≠ 代码可运行**，这是最危险的假信心。

### 10. 资产不仅要"存在"，还要"对"（v3 新增）
门禁查出 `banner.png` 存在即放行，但它：长宽比 0.39、
水平方向 2 个分离前景块 —— 很可能合图没切分，根本不是一面旗。
→ 资产校验要加**形状合理性**：长宽比、前景块数、前景占比区间。

### 11. 超 60s 后台跑，不阻塞对话
前台跑编码测试 → 工具超时 → 对话中断。

### 12. 契约块不写历史
历史占契约块 34%，每次改代码都进上下文 → 历史进 `notes/`。

## 三、分层结构

```
WORKFLOW.md       主干常驻
contracts/*.md    一模块一契约，平均 350 字符
deps.md           依赖契约图
notes/*.md        改动史，不进常驻上下文
enforce.py        门禁
```
改任一块读：主干 + 该模块契约 + 该文件。**不碰其余契约。**
