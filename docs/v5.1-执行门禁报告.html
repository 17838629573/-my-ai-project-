v5.1 · 执行门禁

2026-09-10 · 将不可绕过的硬规则固化为代码执行

概述

此前 v5.1 工作流的 9 条铁律和断点纪律全部是文本规则——写在 WORKFLOW.md 里，靠 AI 自觉遵守，没有任何代码层面的强制力。

本次新增 scripts/enforce.py（执行门禁），将以下硬规则转为实际运行的 Python 脚本。每步过门自动触发，退出码非 0 即阻断流程，无法跳过：

硬规则来源门禁命令触发时机阻断
红区文件保护铁律5check-write <路径>每次写文件前红区无授权 → halt
授权强制检查铁律8check-auth <track>授权操作前无有效track → halt
铁律不可覆盖铁律9check-iron-law <文件>full-check 阶段铁律被删 → halt
断点强制断点节gate post-step N每步过门无 WORKLOG → 不准过
判定有依据铁律1check-evidence <码> [描述]每步过门无依据描述 → 警告
全局完整性—validate入口处脚本缺失/铁律不完整 → halt

代码强制 以上 5 条硬规则写入 enforce.py 运行，失败即阻断。弹性规则（铁律 2/3/4/6/7、规模判断细节、TDD 分支等）保持文本规则不变。

enforce.py 架构

436 行，纯标准库，零外部依赖。6 个子命令各自独立，退出码约定：

  • 0 通过
  • 1 硬规则违例 → 调用方应 halt
  • 2 用法错误

子命令一览

用法:
  enforce.py gate pre-post <步骤名>    步骤前门禁：前置检查
  enforce.py gate post-step <步骤名>   步骤后门禁：WORKLOG 强制校验
  enforce.py check-write <文件路径>    写文件门禁：铁律5 红黄区保护
  enforce.py check-auth <track名>      授权门禁：铁律8 强制查 track
  enforce.py check-iron-law <文件>    铁律保护门禁：铁律9 防覆盖
  enforce.py check-evidence <码> [描述]    判定依据验证：铁律1
  enforce.py validate                     全局完整性检查

# 命中以下路径模式即判定为红区文件，无授权禁止自动修改

授权解析

check-auth 子命令自动查找 .track.md 文件（同名、tracks/、skills/<name>/ 三级），解析到期日：

  • - → 永久有效
  • YYYY-MM-DD 未过期 → 有效
  • YYYY-MM-DD 已过期 / 字段缺失 / 文件不存在 → 阻断

铁律5 · 文件保护 代码强制

规则原文

红区文件（.env、auth、secrets、deploy、CI 配置、依赖文件）禁自动改；黄区（config、routes、models、入口文件）改前告知。

代码实现：check-write

在 skills/write/SKILL.md 中新增第 6 步：写文件前先跑 enforce.py check-write <目标文件>。红区文件无 track 授权 → 退出码 1，调用方必须 halt。黄区文件 → 仅警告（退出码 0），不阻断。

铁律9 · 铁律保护 代码强制

规则原文

铁律不可被后续指令覆盖；删除 / 清空 / 覆盖等不可逆操作，先要用户确认，确认后按铁律 8 落盘。

代码实现：check-iron-law

在 skills/check/SKILL.md full-check 中新增第 6 项：enforce.py check-iron-law WORKFLOW.md。校验逻辑：

  1. 检查 WORKFLOW.md 中是否包含铁律章节（正则 ^\s*#+.*铁律）
  2. 检查铁律编号条数（^\d+\.）是否为 ≥9 条
  3. 任一条件不满足 → 退出码 1，halt

断点强制 · WORKLOG 代码强制

规则原文

每步过门 → 往 WORKLOG.md 追加一行（时间 + 步骤 + 过门产物）；"继续上次"从它定位。

代码实现：gate post-step

7 个主干步骤的过门处全部嵌入 enforce.py gate post-step N。检查 WORKLOG.md 中是否已记录对应步骤名称。无记录 → 退出码 1，不准过。

gate pre-step 负责在步骤开始时确保 WORKLOG.md 存在并自动创建。

铁律1 · 判定依据 代码强制

规则原文

判定靠命令输出（测试通过 / grep 为 0 / 退出码 0），禁止说"应该没问题"。

代码实现：check-evidence

每步过门处同步调用 enforce.py check-evidence <退出码> "描述"。接受整数退出码和依据描述，退出码格式错误 → 阻断；空描述 → 警告。确保每步决策都有可验证的命令输出依据。

工作流嵌入

enforce.py 的调用点已嵌入主干流程的每个关口：

## 主干步骤
步骤1 | 接需求
  gate pre-step 1 → 需求确认 → check-evidence → gate post-step 1

步骤2 | 拆模块
  gate pre-step 2 → 产出契约图 → 用户确认 → check-evidence → gate post-step 2

步骤3 | 写模块
  gate pre-step 3 → 写文件（check-write 每文件触发）→ quick-check → gate post-step 3

步骤4 | 集成
  gate pre-step 4 → full-check（validate + check-iron-law）→ gate post-step 4

步骤5 | 测试找bug
  gate pre-step 5 → 测试 → check-evidence → gate post-step 5

步骤6 | 汇报
  gate pre-step 6 → 汇报 → 用户确认 → check-evidence → gate post-step 6

步骤7 | 交付
  gate pre-step 7 → 交付 → check-evidence → gate post-step 7

## 入口处
  从零做 → validate → 步骤1
  ...

任意步骤的 gate post-step 失败 → 不准过门，流程暂停，读 skills/halt/SKILL.md。
