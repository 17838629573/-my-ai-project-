# SRC 挖洞工作流

**十步主干 · 三条铁律 · 根因族抽象层**  
让挖洞从"看运气"变成"有保底"，每一步可追溯、可校准、不漏扫

</div>

---

## 概述

SRC 挖洞工作流是一套**面向授权众测平台（SRC / Bug Bounty）的漏洞挖掘执行框架**。
它的设计围绕一个核心目标：

> **用最少的规则，让每一步都有判据；用判据换覆盖率，用校准换进化。**

### 它解决什么问题

直接让 AI 挖洞，本质上是**模式匹配**——找长得像已知漏洞的东西。
但 SRC 上真正值钱的洞**长得都不像漏洞**：

- 主资源校验了、子资源没校验
- 列表接口 `pageSize` 调大能拿全量
- 老版本路径没人管，校验比新版松得多
- 同一根因在三个不同协议里各出现一次

这些东西没有任何直觉会指向它们，**只有清单会逼你去测**。

### 为什么它很轻

```
任意时刻上下文 = WORKFLOW.md（常驻）+ 当前步骤的引导提问
```

- 全局铁律**只有 3 条**
- 每一步只有三样东西：**一句话目标 + 一条脚本命令 + 一段引导提问**
- 规则库不一次全读，按批次调取

超过 20 条并列规则，注意力就会开始稀释。所以规则被压缩成铁律，
其余全部转成**散文式提问**——规则替代思考，提问激活思考。

## 核心特性

### ◆ 提问驱动，而非规则驱动

| | 规则 | 提问 |
|---|---|---|
| 模型行为 | 机械匹配条目 | 真正推理 |
| 注意力 | 并列条目互相干扰 | 叙事有结构，抗稀释 |
| 清单外情况 | 不会处理 | 靠理解迁移 |

P3 越权那一步，用三段提问承载了原来八张测试卡的判断逻辑，
但它讲的是"为什么"，不是"做什么"：

> **这些数据本来就该公开吗？**
> 商品列表返回全部商品叫正常功能；订单详情返回别人手机号才叫越权。
> 你要回答的不是"有没有返回数据"，而是"**返回的数据属不属于我**"。

### ◆ 三层分工

| 层 | 谁做 | 做什么 |
|---|---|---|
| **脚本层** | 程序 | 穷举、比对、并发、版本判断 |
| **引导层** | 提问 | 激活心智模型 |
| **模型层** | 模型 | 业务理解、泛化、串联、创造性绕过 |

**判断标准**：这个答案能不能写成可判定的条件？能 → 交给脚本。

### ◆ 反向校准（P0 是第零步，不是准备步骤）

工作流最大的隐患是：**清单是我们自己写的，它只能覆盖我们已经想到的攻击面。**

所以第零步是拿最近三个月的真实漏洞反问工作流：
**「你能发现它吗？」** 定位不到任何步骤的 = 缺口，那才是真正要补的东西。

### ◆ 根因族抽象层（P9）

实证发现：**GitLab SAML 2024、GitLab SAML 2025、UpdraftPlus UDRPC 2026——
三个不同协议、不同产品、不同年份，是同一个根因。**

按漏洞类型串不起来，按协议也串不起来，只有按根因能。
所以有一条铁律：**按根因检索，不按 CVE 检索。**

## 十步主干

```
P0 收割校准 → P1 情报泛化 → P2 资产测绘 → P3 越权未授权 → P4 业务逻辑
→ P5 注入服务端 → P6 补丁对齐 → P7 信任域 → P8 AI边界 → P9 根因族关联
```

## 快速开始

```bash
# 0. 反向校准（用你收集的近三月漏洞）
python3 src_calibrate.py load --file vulns.json

# 1. 挖规则库里的根因族
python3 src_rules.py download
python3 src_rules.py cwe --cwe CWE-347
python3 src_rules.py vendor

# 2. 日常开工：跑完确定性步骤，再输出引导提问
python3 run.py daily --dir ./work

# 3. 只看某一步的引导提问
python3 run.py ask p3
```

## 合规底线

- **仅在授权资产、厂商赏金范围或隔离环境执行**
- 探针必须无害：只读、随机 marker、可逆
- **不用破坏性操作"证明"漏洞**（不删文件、不触发 RCE、不动真实资金）
- 脚本产出未经人工复现，一律不许提交

> ⚠️ 未授权目标不发任何请求。这是底线，不是建议。

---

## 已知边界（诚实说明）

1. **脚本判据只在本地靶场验证过**。相似度阈值 0.85 是拍的，
   真实环境有 WAF / CDN 缓存 / 风控，大概率要调。
2. **泛化假设的实际命中率未实测**，估计 20%-40%，需要用真实目标校准。
3. **目标站点源码无法自动获取**（需人工提供），
   但开源组件源码、公开检测规则库可直接分析。

**这些数字需要通过一次完整实战闭环来兑现。**

## 与本仓库另一工作流的关系

本仓库同时存放 `AI编程工作流`（根目录）与 `SRC挖洞工作流`（本目录）。
两者**完全独立，互不干扰**，可并存使用。

- 根目录 = AI 编程协作（七步主干 · 九条铁律 · 五道门禁）
- `src-hunting-workflow/` = SRC 漏洞挖掘（十步主干 · 三条铁律 · 根因族层）
