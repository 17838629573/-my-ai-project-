# SRC 挖洞工作流清单

> 使用方式：每个新目标复制一份，逐项打勾并填写状态。
> 状态标记：`[ ]` 未测 | `[~]` 测过无果 | `[?]` 疑似 | `[!]` 已确认
> 核心纪律：**不允许跳过，不允许"感觉没问题"。测过无果也要记录排除理由。**

---

## ① 开工前置（不做完不许开测）

- [ ] 确认目标在平台授权资产范围内（域名/IP/APP 包名逐一核对）
- [ ] 阅读该平台测试规范，明确禁止项（常见禁测：DoS、社工、批量拖库、生产数据篡改）
- [ ] 确认是否有速率限制 / 是否允许自动化扫描器
- [ ] 独立浏览器 profile（避免污染主账号 Cookie）
- [ ] 新建 Burp / 代理项目文件，开启全量日志
- [ ] 准备测试账号 ≥2 个（A/B 账号，用于越权验证），建议小号，避免暴露真实身份
- [ ] 建立目标目录：截图 / 请求包 / 笔记，统一命名带时间戳

---

## ② 资产测绘（画攻击面地图）

**域名与入口**
- [ ] 子域名收集（证书透明日志、DNS 记录、搜索引擎、平台资产列表）
- [ ] 主站 / 移动端 / 小程序 / API 域名分别列出
- [ ] 历史 URL（Wayback、快照站）找已下线但未关闭的老接口
- [ ] 接口文档泄露：Swagger、OpenAPI、Postman 分享链接、/api-docs
- [ ] 后台管理入口、运维系统、测试/预发环境

**技术栈指纹**
- [ ] 前端框架（Vue/React/jQuery）、后端框架、中间件版本
- [ ] WAF / CDN 识别（有 WAF 就要预留绕过时间）
- [ ] 云服务与对象存储（OSS/COS/S3 直传、bucket 权限）

**代码与情报**
- [ ] GitHub / 码云 / 网盘搜索：源码、配置、密钥泄露
- [ ] JS 文件审计：硬编码密钥、隐藏接口、source map（.map 文件可直接还原源码）
- [ ] 该厂商**历史漏洞公告**：以前被挖过什么，同类问题大概率换个地方还在
- [ ] 移动端：APK/IPA 反编译拿接口，小程序解包

**输出**：一张资产清单表，标注每项"暴露程度 × 数据价值"，排出优先级。

---

## ③ 功能枚举（按模块列全，不漏项）

对每个模块，固定问三句：**能改哪些参数？改了服务端认不认？有没有服务端校验？**

**认证模块**
- [ ] 登录：用户名枚举、密码爆破限制、锁定机制、验证码可绕过/可复用
- [ ] 注册：手机号/邮箱可重复绑定、批量注册
- [ ] 短信/邮箱验证码：爆破、复用、绑定手机号与验证手机号不一致
- [ ] 密码找回：token 可预测、越权重置他人、仅前端校验步骤
- [ ] 第三方登录 / OAuth：回调地址可控、绑定流程可劫持
- [ ] Token：JWT 弱密钥/算法可篡改（none）、长期有效、退出不失效

**授权模块（SRC 主力产出，重点打）**
- [ ] 水平越权：改 ID / 订单号 / 用户标识，能否读到他人数据
- [ ] 垂直越权：普通用户能否调管理接口
- [ ] 未授权访问：直接删掉 token/Cookie 看是否还能返回数据
- [ ] 接口级权限：GET 能查，POST/PUT/DELETE 是否也放行
- [ ] 多设备/多角色：切换角色后旧会话权限是否残留

**用户资料**
- [ ] 查看/修改他人资料、头像、收货地址
- [ ] 手机号/邮箱换绑流程是否验证原绑定
- [ ] 头像/文件上传点

**业务对象（逻辑漏洞高发区）**
- [ ] 订单：金额、数量、运费、优惠叠加、库存并发
- [ ] 支付：金额篡改、支付回调伪造、重复支付/退款
- [ ] 优惠券/积分/余额：领取并发、重复使用、负数绕过
- [ ] 抽奖/秒杀：并发、次数限制、时间窗口
- [ ] 退款/提现：金额与频次校验

**输入点**
- [ ] 搜索框、评论、留言、富文本
- [ ] 导出功能（Excel/PDF → 关注 XXE、SSTI、公式注入）
- [ ] 导入功能（文件解析 → 关注反序列化、XML）
- [ ] 模板/邮件渲染（SSTI）
- [ ] 重定向参数（开放重定向）
- [ ] URL/参数回显（XSS、SSRF 探测）

**文件上传**
- [ ] 后缀/Content-Type/Magic Number 绕过
- [ ] 解析漏洞、二次渲染绕过
- [ ] 路径可控（写入任意目录）
- [ ] 文件大小/并发导致的存储问题

**服务端漏洞**
- [ ] SQL 注入（含二次注入、ORDER BY 注入）
- [ ] 命令注入 / 代码执行
- [ ] SSRF（内网探测、云元数据 169.254.169.254）
- [ ] 反序列化（Java/PHP/Python）
- [ ] 文件读取/下载（路径穿越）
- [ ] 组件 CVE（依赖版本比对：Shiro、Fastjson、Log4j、Struts 等）

**第三方集成**
- [ ] 支付回调、短信接口、邮件服务
- [ ] OAuth / SSO 流程
- [ ] 云存储直传签名是否可伪造

---

## ④ 测试优先级排序

1. 未授权访问 / 越权（命中率最高，危害明确）
2. 逻辑漏洞（支付、验证码、优惠券）
3. 注入类（SQL、命令、SSRF）
4. 文件上传 / 模板渲染
5. 配置与组件 CVE
6. 信息泄露 / 前端密钥

**双遍法**：第一遍广度——所有功能点过一遍打状态；第二遍深度——只攻标记为 `[?]` 的点。

---

## ⑤ 验证与取证

- [ ] 用**最小危害 payload** 证明可利用（不拖库、不改生产数据、不破坏服务）
- [ ] 证明"能读到别人的数据"即可，不要真导出
- [ ] 截图：请求包 + 响应包 + 界面效果，三样齐全
- [ ] 确认可稳定复现（重放 ≥2 次）
- [ ] 敏感信息脱敏后再留存到笔记（域名、真实账号、Cookie）

---

## ⑥ 定级与报告

报告结构：
1. **标题**：组件/功能 + 漏洞类型 + 影响面，例：`订单接口未授权访问可遍历全站订单`
2. **影响范围**：哪个域名/接口、影响多少用户/数据
3. **复现步骤**：编号 1、2、3……每一步可执行，别人能照着跑通
4. **PoC**：脱敏的请求包（可直接复制重放）
5. **危害证明**：截图（打码敏感项）
6. **修复建议**：具体到代码/配置层面，不要只写"加强校验"

自查清单：
- [ ] 换成新手照着步骤能复现吗？
- [ ] 危害描述是否说清"能造成什么后果"而非只说技术名词？
- [ ] 修复建议是否可落地？

## 常见漏扫原因（自检用）

| 漏在哪 | 表现 | 对策 |
|---|---|---|
| 只测主域名 | 漏掉子域、API 域、老接口 | 做完资产测绘再开测 |
| 只测看得到的功能 | 漏掉隐藏接口、v1/v2 老版本 | 审 JS、找 Swagger、试版本号 |
| 只跑扫描器 | 逻辑漏洞全漏 | 手工过功能枚举清单 |
| 只测有参数的地方 | 漏掉无参数接口的越权 | 每个接口都试删 token |
| 改了参数看前端 | 被前端校验骗过 | 一律用 Burp 改包，不信任前端 |
| 没记录排除项 | 重复劳动 / 误判 | 强制填状态与排除理由 |
