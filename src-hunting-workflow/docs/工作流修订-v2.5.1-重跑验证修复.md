# 工作流修订 v2.5.1：重跑验证发现的三处修复

> 触发：v2.4 重跑执行报告（另一 AI 端到端实跑）
> 性质：**本次修订全部来自外部验证反馈，不是我自己想到的**

---

## 一句话总结

**v2.4 我加的代码有 2 个运行时 bug，自己没发现，是重跑的 Agent 抓出来的。**

这件事本身比修 bug 更值得记——见文末「最该记住的一条」。

---

## 修复 1 · R3 段非知名覆盖率 KeyError（bug#1）

**现象**：`r[1] > 0` 对 dict 解包 → `KeyError: 1`

**根因**：`calibrate()` 返回的是 dict 列表
（`{"title":..., "covered":..., "steps":[...]}`），
我写的时候当成了 `(key, count)` 元组对。

```python
# 错误
covered = len([r for r in nrows if r[1] > 0])
# 修复
covered = len([r for r in nrows if r["covered"]])
```

同时把 `for k, c in nrows` 改成用既有的 `contribution(nrows)` 统计。

---

## 修复 2 · R2 段零命中 ValueError（bug#2）

**现象**：`[k for k, c in rows if c == 0]` 对 dict 列表元组解包 → ValueError

```python
# 错误
zero = [k for k, c in rows if c == 0]
# 修复：用既有的 contribution() 统计，再对照全量步骤
_contrib = contribution(rows)
zero = [k for k in STEPS if _contrib.get(k, 0) == 0]
```

**顺带改进**：原来只统计"出现过的步骤"，改后对照 `STEPS` 全量——
**没被任何样本命中的步骤现在也会列出来**，不会漏。

## 修复 4 · coord 多行 YAML 只取首行

**现象**：nuclei 模板的 `description: |` 块标量，正则只取到 `|`，内容丢失。

**修复**：`one()` 增加块标量处理——检测 `|`/`>`/`|-`/`>-`/`|+`，
然后按缩进收集后续所有行。

实测：
```
description: |
  This is a multi-line
  description block that
  spans several lines
→ "This is a multi-line description block that spans several lines"
```

## 最该记住的一条

**这两个 bug 都是我在"加功能"时写进去的，本地没跑通就上传了。**

v2.4 我加 R3/R2 时用的是新逻辑，却没做混合样本回归——
只跑了单一场景，恰好没触发 tuple/dict 的分支。

而它被另一个 Agent 在**第一次真实使用**时就抓到了。

这正好印证了工作流自己的道理：

> **设计者验证不了自己的设计。**

我们 P0 那条"反向校准"是为了发现工作流看不见的漏洞；
这次则说明**代码本身也需要外部跑一遍才算数**。

所以新增一条纪律（写入 MANIFEST）：

> **任何新增脚本逻辑，必须跑混合样本回归（至少含 1 知名 + 1 非知名 + 1 零命中场景）再上传。**
