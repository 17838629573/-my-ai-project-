# 版本 → 组件 → CVE：<厂商B·站群> 9.x 全系缺陷链（<target> 案例）

> 来源：<厂商B·站群>官网公开公告 + 官方版本对应表（chinawebber.com）
> 用途：把「版本号」翻译成「这个版本具体有哪些毛病」
> 合规：本文只做情报映射，不含任何 payload；验证动作见第五节

---

## 一、官方版本对应表（关键，且有个更正）

<厂商B·站群>官网《关于 9.9.x 及之前版本网站群系统的补充说明》（info/1008/3181.htm）：

| 软件著作权版本号 | 内部版本号 | Tomcat 版本 | 状态 |
|---|---|---|---|
| （早期无著作权号） | 9.1.X · 9.2.X · 9.3.X · 9.4.X | **Tomcat <版本族·EOL>** | EOL，**2025-07-30 已停服** |
| **V6** | 9.5.X · 9.6.X · 9.7.X · 9.8.X | **Tomcat <版本族·EOL>** | EOL，**2025-07-30 已停服** |
| **V10** | **9.9.X** | **Tomcat <版本族·EOL>** | Tomcat EOL，暂继续支持，停服待公告 |
| — | 10.1.X · 10.2.X | Tomcat 8.5.x | Tomcat EOL，暂继续支持 |

### 更正：9.9.x ≠ <站群产品>

**9.9.x 对应的著作权版本是 V10，不是 <站群产品>。**

<站群产品>（著作权名「<厂商B·站群>网站群管理平台软件[简称:<站群产品>]V9.0」，登记号 2011SR031802，首次发表 2009-08-01）是更早的命名。

### 但这个更正不影响结论——反而让结论更硬

**注意表格里 Tomcat 那一列：9.1.X 到 9.9.X 全部是 Tomcat <版本族·EOL>。**

也就是说，**不管 <target> 具体是 9.1 还是 9.9，底层都是 Tomcat <版本族·EOL>**。

版本不确定性被这张表消除了——不需要精确版本号，整个区间共用同一个中间件。

## 二、官方公告自认的 EOL 组件清单

《停止维护公告》（info/1008/3172.htm）原文列出的停服原因：

```
9.9.x 及之前版本所依赖的多项上游基础组件已 EoL：
  · Apache Tomcat 7.x       —— 2021-03-31 官方停止维护
  · PostgreSQL 9.2          —— 已停止安全更新
  · Apache HTTP Server 2.2/2.4 部分版本 —— 已进入停更周期
  · 其他历史框架及前端库     —— 不符合行业安全要求
```

**这是厂商自述的依赖清单，比任何第三方推测都可靠。**

并且公告明写：

> 停止提供任何安全补丁和漏洞修复
> 若继续使用停服版本，重大安全漏洞**无法打补丁**

**→ 在这个版本上找到的问题，是不会被修的。**

## 三、Tomcat <版本族·EOL> 已知问题（这就是「这个版本号的毛病」）

### ★★★★★ CVE-2020-1938 · Ghostcat（幽灵猫）

| 项 | 内容 |
|---|---|
| 成因 | AJP 协议对请求属性处理不当 |
| 影响 | Tomcat 9 < 9.0.31 · 8 < 8.5.51 · **7 < 7.0.100** · 6 全版本 |
| **默认状态** | **AJP Connector 默认开启，监听 0.0.0.0:8009** |
| 危害 | 读取 Tomcat 所有 webapp 目录下**任意文件**（配置、源码）；若站点有上传功能 → 文件包含 → **RCE** |
| 修复 | 升级到 7.0.100，或关闭 AJP，或配 `requiredSecret` |
| 备注 | 由长亭科技发现，在 Tomcat 中**潜伏十余年** |

**为什么这条排第一**：
1. 默认开启（不需要任何非默认配置）
2. 影响整个 9.x 内部版本区间（都跑 Tomcat 7）
3. <厂商B·站群> 9.9.x 及之前已停服 → **不会被修**
4. 是读文件，危害直观、可提交性强

### ★★★ CVE-2018-1305 / CVE-2018-1304 安全约束绕过

- servlet 注释定义的安全约束只在加载后应用一次，依赖加载次序
- 某些约束不生效 → 资源暴露给未授权用户
- 影响 7.0.0–7.0.84，修复 **7.0.85**

### ★★★ CVE-2019-0232 Windows RCE

- Windows + `enableCmdLineArguments` 开启时，CGI Servlet 可 RCE
- 影响 7.0.0–7.0.93
- **CGI Servlet 默认禁用** → 需确认是否开启才适用

### ★★ CVE-2017-12617 JSP 上传 RCE

- `readonly=false` 时可 PUT 上传 JSP
- Tomcat 7 默认 `readonly=true` → 需确认配置

### ★★ CVE-2016-8735 JMX 反序列化 RCE

- 影响 7.0.0–7.0.76 区间，JMX 端口暴露时适用

### PostgreSQL 9.2 / Apache 2.2（官方清单里的另两项）

- 需要知道实际部署是否用到、版本是否匹配
- 优先级低于 Tomcat（Tomcat 是官方明确点名且全区间共用）

## 四、验证顺序（只读、低频、单次）

| # | 动作 | 请求/连接数 | 判据 |
|---|---|---|---|
| 1 | 确认 AJP 8009 是否可达 | 1 次连接 | 端口开放 ≠ 存在漏洞，但开放 = 高危信号 |
| 2 | 确认 Tomcat 版本区间 | 1-2 | 错误页 / 静态资源 / 已知路径特征 |
| 3 | 确认是否 Windows（决定 0232 适用性） | 1 | 响应头 / 错误路径分隔符 |
| 4 | 确认 CGI Servlet 是否启用 | 1 | 存在 `/cgi-bin/` 类路径 |
| 5 | 按版本对齐其余 CVE | 0（情报层） | 版本在区间内才测，不盲打 |

**第 1 步是最轻量的**——一次 TCP 连接就能定性，比任何 payload 都省。

## 五、三条必须守住的边界

### 1. 授权范围先确认

<target> 的 www 主站在 EDUSRC 收录范围内，但 **8009 端口是另一个服务入口**。

**不在明确授权范围内的端口，不要扫。** 这条比技术判断优先。

### 2. 这是「验证」不是「打击」

发一次连接看响应差异 = 验证，命中即停。
批量打 payload、尝试读文件、尝试 RCE = 越界。

**SRC 是发现并报告，不是打进去。** 拿到数据的那一刻就已经越界了。

### 3. 前面有网关

<target> 主站确认有统一网关（<LEN-1693> 统一 404 模板）。
AJP 8009 大概率不对公网开放——**测不到是正常的，不等于没有**。

真正可能在的位置：**子域独立部署的业务系统**（authserver、my、webmail 等），
它们可能不共用主站的网关策略。

## 六、这条思路本身的复用价值

「版本号 → 依赖组件 → 组件 CVE → 该版本必然存在」

这个链条成立的前提是**厂商公开了版本-组件对应关系**。

<厂商B·站群>这个案例特殊在于它**上市了**——北交所上市问询回复、招股说明书、法律意见书里
有逐版本的著作权登记信息和功能演进说明。

**上市文件是闭源商业软件最好的情报源**，比 CVE 库还全。

同类可用：
- 北交所 / 科创板 / 创业板招股书（产品版本、客户名单、技术栈）
- 政府采购网单一来源公示（会写明「原系统版本 X，风险值 9.8，需升级」）
- 厂商退市 / 停服公告（明确列出 EOL 组件清单）← **本案例用的就是这个**

**退市公告是其中最值钱的**——它直接给出「哪些组件不再有补丁」。
