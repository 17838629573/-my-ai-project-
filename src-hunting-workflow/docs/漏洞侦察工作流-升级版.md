# 漏洞侦察工作流（升级版）

适用：Web 安全测试，尤其站群/多子系统场景
核心原则：**先读目标，再发请求；先建基线，再判结果；先联网，再定级**

---

## 阶段 0 · 资产盘点（零请求）

| 动作 | 要点 |
|---|---|
| DNS/IP 收敛 | 同 IP 不等于同系统，可能是多套独立部署 |
| 子域枚举 | 每个子域独立建档 |
| 组件识别 | 从已有页面/报错提取，不额外发请求 |
| **资产价值分级** | 决定请求预算分配 |

**资产价值分级（决定投入比例）**：
- **一级**：含个人敏感数据（教务/成绩/学籍/财务/医疗）
- 二级：统一认证、后台管理
- 三级：公开内容站、统计类

**教训**：本项目在三级资产（点击计数端点）上耗了十几轮，而一级资产（jwmis 教务系统）几乎零投入。请求应按价值分配，不是按发现顺序。

---

## 阶段 1 · 响应基线建立（最重要，新增）

**对每个面，先用"绝不可能存在的随机路径"取基线。**

```
GET /{随机串}          → 网关层响应
GET /{随机串}.jsp      → 应用层响应
GET /{已知前缀}/{随机}.jsp  → 鉴权层响应
```

**建立该目标的"响应字典"**：

| 状态 | 典型含义 |
|---|---|
| 网关 404 | 路径不在白名单前缀 |
| 应用 404 | 已放行，但文件不存在 |
| 鉴权页 | 被登录前置接管 |
| 200 + 内容 | 存在且免鉴权 |
| **0B** | **受理但无回执（单独标记）** |
| 400/500 + 栈 | 容器/框架层，泄技术栈 |

**每条记录必须包含**：状态码 + Content-Type + Content-Length + md5 + 前 200 字节。

**硬性要求**：
1. **每个面独立建基线**，不假设跨实例同构（实测 news 与主站网关策略不对称）
2. **0B 单独处置**：0B 只能证明"没输出"，不能证明"没逻辑"；可能掩盖了已发生的写入
3. **不只看状态码**：`image/gif` 那次证明，200·0B 与 200·1135 是天壤之别

**教训**：前 215 个请求全废，因为一直在网关层拿同一个模板，从没进到能"对话"的应用层。**"0 命中"常常不是"没洞"，是"没穿透"。**

---

## 阶段 2 · 目标自述路径提取（新增，优先于字典）

**在发任何探测请求之前，先把目标自己写的页面读完。**

```
1. 抓首页 / 登录页 / 关键功能页源码
2. 编码处理：GBK/UTF-8 先 iconv 转码再 grep（否则中文关键词 0 命中）
3. grep href= / onclick= / action= / ajax URL / 路径拼接变量
4. 提取 JS 中的路径拼接前缀（如 _webRootPath = "/hsjw/"）
```

**输出**：目标自述的真实路径清单。

**为什么优先**：通用字典命中率接近零；目标自述路径命中率高一个数量级。本项目十几轮后才从 jwmis 登录页提取出 10 条真实功能路径（含"查看成绩"），而这些路径**历史上零探测记录**。

**教训**：一直在猜 `/examples/`、`/manager/` 这类通用路径，而目标早就把功能路径写在登录页上了。

---

## 阶段 3 · 形态探测（新增核心）

**形态分流是普遍现象，不是特例。** 同一目标上已两次证明：

| 形态 | 主站 /examples/ |
|---|---|
| 目录 `/examples/` | 1693B 网关页（被拦） |
| 文件 `/examples/index.jsp` | **2455B 应用页（穿透）** |

**所以对每条路径必须测多形态**：
- 目录形态 `/xxx/`
- 文件形态 `/xxx/index.jsp`、`/xxx/index.html`
- 后缀变体 `.jsp` / `.html` / `.action` / `.do`
- 编码形态 `%2e` / `%2f` / `%252f`（双重编码）

**判据**：对照阶段 1 的字典，看返回落在哪一态。

**教训**：用目录形态测出"网关未放行 → 面闭合"，是**判据错误**，只证明了"这种形态被拦"。本报告两轮都犯了此错，直到用 `.jsp` 形态才穿透。

---

## 阶段 4 · 鉴权边界测绘

用阶段 1 的基线判据，逐条测鉴权状态。

**措辞红线（必须遵守）**：
- ✅ "未观察到鉴权拦截"
- ❌ "已确认无鉴权"

理由：非鉴权页响应（如 0B）只能证明"没被拦"，不等于"无鉴权"。

**输出**：免鉴权区地图。

---

## 阶段 5 · 联网 CVE 映射（强制）

**禁止凭模型内部知识定级。必须联网搜索。**

搜索要点：
1. **拉最新年份的 CVE**（本项目报告停在 2025 库，漏掉 2026 年发布的一大批）
2. **注意影响范围边界值**：如 9.0.108 正好是 CVE-2025-55752 受影响范围的最后一个版本
3. **区分是否有补丁**：EOL 分支官方明确不给补丁（Tomcat 7 / 8.5.x）
4. **区分真实危害**：CVE 标题可能误导（CVE-2025-55754 标题像 RCE，实为 ANSI 控制台操纵，官方列 Low）
5. **区分触发前提**：默认配置是否触发、需不需要特定组件（如 RewriteValve、PUT、HTTP/2）

**"运行未修复组件"是独立可提交项**，三判据：
- 版本精确可证（目标自身打印 > 栈类名推断 > 厂商映射）
- 命中公开 CVE 且未修复
- 资产重要性

**不要把"我利用不了"写成"所以没有漏洞"。**

---

## 阶段 6 · 根因聚类与横向移动

**不要在同一端点纵向深挖，要横向移动到同根因的更高价值实例。**

```
低危信号 → 抽根因 → 找同根因的更高价值实例
```

本项目示例：6 条低危 → 4 类根因 → 1 类（接口未鉴权）合并升中危。

**同时验证跨实例**：若同一根因在多个实例普遍存在，报告中写"跨 N 实例普遍存在"，分量显著提升。

**教训**：在点击计数端点上纵向深挖十几轮，参数语义全摸清了，但它还是点击计数。**根因是"未鉴权"，而更高价值的实例在别处。**

---

## 阶段 7 · 定级与措辞

| 发现 | 定级 |
|---|---|
| 文件存在性判别（200 vs 404） | **低危**，且通常不算漏洞（HTTP 基本行为） |
| 目录列表 CWE-548 | 低危（CVSS 5.3） |
| 报错页泄露中间件版本 | 低危 |
| 用户枚举（CWE-204） | 可至中危 |
| 未授权访问敏感数据 | 中危~高危 |
| 运行未修复已知 CVE 组件（敏感资产） | 中危~高危 |

**措辞红线**：
- 危害写到实际验证的那一档，**不夸大**
- 未实际触发的，必须附"未触发声明"（引授权条款）
- 不写"可写入任意数据/可执行代码"（除非验证过）

---

## 贯穿全程的纪律

| 项 | 要求 |
|---|---|
| **请求预算** | 给够，每个请求带判据表。预算不足会导致执行方用"请求少"当模糊借口 |
| **授权条款** | 写在任务书开头，引平台原文，明确"纯观察型 GET"层级 |
| **可写操作清单** | 单独列出并全程封存，每轮报告末尾复核 |
| **间隔** | ≥7s，分时段跑（已观察到约 3 个请求可触发限流） |
| **记录** | Content-Type + CL + md5，不只记状态码 |
| **编码** | GBK 页面先 iconv 再 grep |
| **快照** | 注意 Cache-Control，md5 一致只能证明同一缓存周期 |

## 各阶段常见失败模式

| 阶段 | 失败模式 | 表现 |
|---|---|---|
| 1 | 没建基线 | 215 请求拿到同一个模板，0 命中 |
| 1 | 0B 当无结果 | 掩盖真实逻辑，甚至掩盖已发生的写入 |
| 2 | 跳过读页面 | 在通用字典上耗光预算 |
| 3 | 单形态探测 | "面闭合"实为形态被拦 |
| 5 | 凭模型定级 | 漏掉最新 CVE、误判 CVE 危害 |
| 6 | 纵向深挖 | 低价值端点挖到底仍是低危 |
| 7 | 方法当漏洞 | 提交"响应差异枚举"被打回 |

---

## 一句话总结

**原来的流程问"这个路径有没有洞"，升级后问"目标自己说了什么、这个目标的响应分几层、我这个探测形态对不对、联网查到的最新情况是什么"。**
