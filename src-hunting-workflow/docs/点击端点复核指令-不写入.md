## 一、为什么禁止写入（先读懂再动手）

`addclicktimes.jsp` 是加点击数的端点。

**实测确认写入落在后端持久化存储，不是前端、不是内存**——依据：用 curl（不执行 JS、无 localStorage）请求仍返回真实值 <ID>，且多次请求返回同一数值。

所以：

- **打一次 = 目标真实统计永久 +1**
- **删不掉**——响应里看到的只是服务端发来的拷贝，真实记录在数据库里
- **想删就得再发一个写请求 = 第二次越权，比第一次更严重**

EDUSRC 官方条款明文："不修改、不增加、不删除被测试网站的相关数据。"

**结论：这条只能通过读源码来定性，不能通过打请求来验证。**

## 六、危害描述的正确写法（提交时用）

✅ 可以写：
> 存在未鉴权的写入接口，任意攻击者可篡改业务统计数据，破坏数据完整性；该免鉴权模式若存在于其他写端点，后果更严重。

> "可写入任意数据" / "可执行代码" / "已验证存在"

理由：参数全是数字型（脏数据回退 -1），只能改数字，不能写文件、不能执行代码、不能提权。

❌ 也不能写"已确认无鉴权"——只能写"**未观察到鉴权拦截**"（0B 不等于无鉴权的证明）。
