# 工作流升级 v2.5：确定性规则硬化

> 触发：实测发现 WORKFLOW.md 557 行里引导提问只占 21%，
> 而"必须/禁止/一律"这类要记住并执行的措辞出现 44 次
> 升级内容：新增 `src_gate.py` 六闸门 + 主干文档瘦身 557→458 行

---

## 一句话总结

**把可判定的规则搬进代码，文档只留提问。**

这不是优化，是角色重定义：工作流从
「**AI 按文档执行，脚本辅助**」变成
「**AI 是编排器，代码是判定器，AI 只负责提出假设和判断意义**」。

---

## 为什么要硬化：实测数据

硬化前的 WORKFLOW.md 构成：

| 内容 | 行数 | 占比 |
|---|---|---|
| 引导提问（真正激活思考的） | 117 | **21%** |
| 表格硬规则 | 68 | 12% |
| 普通段落（大量是规则说明） | 155 | 28% |
| **"必须/禁止/一律"类措辞** | **44 次** | — |

**激活思考的只占两成，要记住并执行的规则占了四成。**
这跟我们最初定的原则（超过 20 条并列规则注意力就会稀释）正好相反。

### 问题的本质

规则是要**记住并逐条比对**的——58 行表格 + 44 次硬性措辞，
AI 每做一步都得扫一遍，这是**持续占用**。

提问是**读完就理解**的叙事，不占驻留。

## 升级 1：新增 `src_gate.py`（六闸门）

```bash
src_gate.py rate       --platform <平台> --rps <值>    # 限速合规
src_gate.py evidence   --file items.json               # 证据链四项
src_gate.py merge      --file items.json               # 同根因合并判定
src_gate.py intel      --epss <值> --kev --cve <CVE>   # 情报三层验证
src_gate.py quota      --add N                         # 注意力配额
src_gate.py preflight                                  # 开工前置检查
src_gate.py rules                                      # 打印全部硬规则
src_gate.py check ...                                  # 一次跑完
```

### 实测效果

**限速**（差两个数量级，用错即违规）：
```
[FAIL] atmail: 设定 20.0 req/s vs 上限 5 req/s
   [x] 超出限速 —— 违规风险，必须调低
```

**证据链**（Atmail: scanner output 必须 manually confirmed）：
```
   [x] 订单越权 —— 缺: verdict, precondition
   [OK] 用户信息泄露
判据：交给不了解目标的人，能不能照着证据独立复现？
```

**合并**（EDUSRC: 多处相似漏洞降等级）：
```
● 根因=缺失鉴权 CWE=CWE-639 共 3 条
   → [!] 应合并为一份，按整体影响面定级
```

**情报**（EPSS>0.5 或 KEV 强制三层）：
```
   [x] 未完成 3 层 —— 该情报暂不可用于优先级决策
```

**配额**（发散会爆炸）：
```
   待验证假设: 8/10
   [!] 接近上限，优先验证已有假设，不要再发散
```

| 指标 | 硬化前 | 硬化后 |
|---|---|---|
| 总行数 | 557 | **458**（-18%） |
| 引导提问占比 | 21% | **24%** |

| 硬性措辞 | 44 次 | 大幅减少 |

**提问一行没删**（实际占比还升了，因为分母变小了）。

### 具体做了什么

- P0 段的样本构成/零命中处置/情报验证 → 交给 `src_calibrate.py` + `src_gate.py`
- 限速表 → 内置八个平台上限到 `src_gate.py rate`
- 状态标记分界线 → `src_gate.py evidence` 判定
- 证据链要求 → 四项必备，缺一拦下
- 同根因合并 → `src_gate.py merge` 自动聚合
- 注意力配额 → `src_gate.py quota` 计数拦截
- 删除重复的「三层分工」段和元说明段

## 升级 3：一个之前没想到的收益

**硬化的真正价值不是准确，是可审计。**

代码判定留下的是**数值**：
`sim_to_owner=0.97`、`status_before/after=200`、`reject_word_hit=None`

AI 判断留下的是**自然语言**："疑似存在越权"

**前者可被第三方复核，后者不可。**

在 Atmail 那种规则下（三次无效报告 → 半年封禁），
可复核性是保命的东西——你提交时能附上判定数值，人家能照着验。

## 必须卡住的边界

**硬化的是判据，不是路径。**

| ✅ 硬化 | ❌ 不硬化 |
|---|---|
| 什么叫命中 | 往哪找 |
| 够不够格提交 | 这个根因像什么 |
| 限速多少 | 要不要换角度 |
| 证据够不够 | 业务语义判断 |

**如果连"往哪想"都硬化了，AI 就退化成脚本执行器——那还要模型干什么。**

我们最值钱的部分恰恰是那些没法写成条件的：业务理解、串联、创造性绕过。

**薄的下限是「提问 + 编排指令」。** 再薄，AI 就不知道自己该干什么了。

---

## 一个新出现的风险（尚未解决）

硬化之后，AI 出错的方式从「**判断错**」变成「**编排错**」：

- 该调 `src_scout.py` 却没调
- 参数填错（`--delay` 没按平台改）
- 脚本报了疑似它没读进去

**这是完全不同的一类错误，现有纪律一条都没覆盖。**

不过它比"判断错"好处理——编排错有明确信号（脚本没跑、参数越界），
判断错是静默的。

下一步需要补**编排层纪律**，否则新失败模式没人管。

## 已知边界

1. **编排层纪律缺失**——硬化后 AI 可能跳过脚本或填错参数，目前无检查。
2. `src_gate.py` 的闸门是**拦截不是修复**——它告诉你不合规，不帮你改。
3. 平台限速表只收录了 7 个平台，未收录的按最保守值（1 req/s），可能过于保守。
