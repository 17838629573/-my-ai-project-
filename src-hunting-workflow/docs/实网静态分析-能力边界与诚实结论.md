## 一、为什么做不出源码级静态分析

我做了实测，不是推断：

| 尝试 | 结果 |
|---|---|
| 抓 `<REF-SRC-PLATFORM>` 页面源码 | 只返回公告文本，无 script / JS 路径 / API 路径 |
| 抓 `austin-dev.gleague.nba.com` | 只返回 "NBA Login / Username / Password / Remember me / Login" |
| 抓 `dev.stats.gleague.nba.com` | 同上，仅可见文本 |
| **明确要求返回 `<form>` 的 action/method、input 的 name/id/type、hidden input、HTML 注释** | 明确返回："No form tag, input tags, hidden inputs, or HTML comments are present in the extracted content" |
| 抓 `/robots.txt` | 返回的是同一个登录页，拿不到原始内容 |
| 抓 raw JS 文件（cdnjs） | 失败，不支持该内容类型 |
| 抓 `raw.githubusercontent.com` | 失败 |

**结论：取到的是"渲染后的可见文本"，不是 HTML 源码。**

`<script>`、`<script src=...>`、内联 JS、form 属性、hidden input、注释——这些**全部被剥离**。

而静态代码分析的对象**恰恰就是这些**。
拿不到它们，就做不了源码级分析——**只能做文本层观察**。

## 二、严格区分：观察到的 ≠ 漏洞

有两条观察，但它们**都不是漏洞**，我按工作流 P0 的纪律标注清楚：

### 观察 1：dev/qa 子域暴露登录入口

`austin-dev.gleague.nba.com` 与 `dev.stats.gleague.nba.com` 均返回登录页。

- **这是漏洞吗**：不是。登录页存在是正常的。
- **为什么仍值得记**：这两个是 `-dev` 后缀子域，且在公开赏金范围内。按工作流 P2，"别人不会去看的入口"是高产区——但这只是**方向**，不是发现。
- **要变成疑似项，还需要什么**：需要证明该环境用的是弱凭证、默认口令、或连接了生产数据。**这需要发包验证，我做不到，也没做。**
- **状态**：`[~]` 观察项，非疑似漏洞

### 观察 2：两个子域的登录页 UI 不同

`austin-dev` 是朴素登录框，`dev.stats` 用了 Material 图标（`account_circle` / `vpn_key`）。

- **这是漏洞吗**：不是。
- **可能的意义**：两个环境可能由不同团队/不同时期部署，**技术栈不一致**——按 P7 维度，不同入口可能存在不同校验强度。
- **状态**：`[~]` 观察项，非疑似漏洞

## 三、为什么我不编造"疑似漏洞"

这一轮很容易产出看起来很唬人的东西——比如"dev 环境可能存在弱口令""可能存在未授权访问"。

**但我没写。原因是：Atmail 的规则把这类产出定性得极其清楚：**

> "Reports that consist of unverified tool output, **speculative or fabricated findings**, hallucinated code paths or endpoints, or apparent unedited AI generation may be closed without response."
>
> "Repeat-invalid throttle: **three or more invalid reports within 90 days → 6 个月封禁**"

**"可能存在"不是发现。** 按我们自己工作流的纪律——脚本产出未经人工复验不算漏洞，泛化推导出来的是假设不是发现——同理，**连源码都没看到就下的结论，连假设都算不上，只能是臆测**。

拿去提交，只会砸信誉分。

## 五、本轮的真正收获

不是漏洞，是两条**关于工具边界的认知**，它们直接影响工作流设计：

**1. 我的 web 抓取只能拿"渲染后文本"，拿不到源码。**
→ 工作流里凡是需要看源码的步骤（P1 泛化里的补丁 diff、P5 的语义复活化链路、P7 的内部头分析），**都必须由你提供素材**，我不能自动完成。
→ 手册里应该明确标注：**P1/P5/P7 依赖外部输入，不是自足步骤。**

**2. "疑似"和"臆测"的分界线必须写死。**
→ 疑似 = 脚本/观察给出了**客观差异**（如两版本响应不同、换凭证返回他人数据）
→ 臆测 = 只有推理链、**没有任何客观差异支撑**
→ **只有前者能进入验证队列，后者一律丢弃。**

这条要加进工作流的提交纪律。
