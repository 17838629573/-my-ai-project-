# SRC 极简执行手册（提问驱动版）

> 设计原则：**规则替代思考，提问激活思考。**
> 凡是脚本能判定的，一律交给脚本；模型只做脚本做不了的事——理解意义。

---

## 一、三层分工

| 层 | 谁做 | 做什么 | 特征 |
|---|---|---|---|
| **脚本层** | 程序 | 穷举、比对、并发、版本判断 | 结果确定，不需要思考 |
| **引导层** | 提问 | 激活心智模型，指明思考方向 | 不是规则，是问题 |
| **模型层** | 模型 | 业务理解、模式泛化、串联、创造性绕过 | 脚本做不到的才动用 |

**判断某一步该放哪层的标准**：
这个问题的答案，能不能写成一个可判定的条件？
能 → 脚本层。不能 → 引导层或模型层。

---

## 二、全局铁律（只有 3 条）

1. **授权范围内，最小危害**——证明可利用即可，不拖库、不改生产数据、不动真实资金。
2. **不信任前端**——一切限制以改包后的服务端响应为准。
3. **脚本能判定的，不动脑**——把注意力留给业务理解和串联。

就这三条。其余全部按需加载。

---

## 三、批次（每批只有：一句话目标 + 脚本命令 + 引导提问）

### P0 · 资产测绘

**目标**：知道该打哪里，不打哪里。

**脚本**：
```bash
python3 run.py p0 --host https://target.com
```

**引导提问**（跑完再看）：
> 这些人里，哪一个最值钱？判断标准不是"哪个好打"，而是"哪个被打之后后果最严重"。
> 一个存着手机号的后台，价值远高于一个静态官网，哪怕后者更好打。
>
> 再问：哪些入口是别人不会去看的？主站页面上能点的功能，几百人已经测过了。
> 真正出货的是那些不在页面上、但确实在跑的东西——老版本接口、内部路径、
> 移动端专用域名、几个月前下线但没关掉的服务。

---

### P1 · 越权与未授权

**目标**：找出"谁都能拿到谁的数据"。

**脚本**：
```bash
python3 run.py p1 --req req.txt --ids ids.txt --param orderId \
    --cookie-a "session=A" --cookie-b "session=B"
```

**引导提问**：
> 脚本告诉你哪些请求在删掉凭证或换凭证后仍返回数据。但先想清楚：
> **这些数据本来就该公开吗？**
> 商品列表返回全部商品叫正常功能；订单详情返回别人手机号才叫越权。
> 所以你要回答的不是"有没有返回数据"，而是"返回的数据属不属于我"。
>
> 确认属于别人后，问第二层：**同一批代码写的其他接口呢？管理端呢？老版本路径呢？**
> 一个接口越权是低危，同一根因的一批接口越权就是高危。
>
> 最后问：**如果这么明显，为什么之前没人报？**
> 答案常是"有 WAF"、"需特定配置"、"没人测到这里"。想清楚再投入时间。

---

### P2 · 业务逻辑

**目标**：找出"服务端算错了"。

**脚本**：只能帮忙做并发（可用 Intruder 或自写），其余做不了。

**引导提问**：
> 打开目标，像真实用户那样用一遍，然后问：
> **这笔钱、这张券、这个库存，服务端眼里到底是怎么算的？**
> 如果下单请求里带着金额字段，多半有问题——金额本该服务端算出来，不是从请求里读。
>
> **这里的"限制"是真的限制吗？** "每人限领一张"写在页面上还是服务端？
> 如果是前者，同时发二十个请求试试。单线程测必定正常，必须并发。
>
> **这些步骤能跳过吗？** 直接请求最后一步，看后端认不认。

---

### P3 · 情报泛化

**目标**：从别人的一个洞，看出他没看出来的东西。

**脚本**：
```bash
python3 src_intel.py demo --top 10      # 情报打分排序
python3 src_variant.py demo --top 6     # 模式泛化推导
```

**引导提问**：
> 拿到报告先别急着复现。问：
> **他改的参数为什么会生效？缺的是哪一道校验？** 这是根因。
>
> **这个根因还可能藏在哪？** 同模块其他接口、反方向操作（能读就能改吗）、
> 换 HTTP 方法还灵吗、老版本路径呢、移动端呢。
>
> **如果防护是黑名单，等价写法有多少种？** 黑名单几乎总能绕。
> 编码、大小写、路径分隔符替换、IP 进制、域名指回。
>
> **最重要：如果这么明显，为什么原作者停在这里？**
> 他很可能不是没想到，是试过没成。想清楚这个再动手。

---

### 报告

**引导提问**：
> **不了解这个目标的人，照着我的步骤能复现吗？** 不能就回去补——这是被打回最常见的原因。
>
> **我写的是业务后果还是技术名词？**
> "存在越权漏洞"没有信息量；"任意登录用户可遍历全站订单，含手机号与收货地址，实测 N 条"才叫危害。
>
> **修复建议落到代码层面了吗？** "加强校验"不算；
> "在 XxxService.getOrder 中比对 order.userId 与当前登录用户"才算。

## 四、随时可调出提问

```bash
python3 run.py ask p1      # 单独看某批的提问
python3 run.py ask         # 看全部
python3 run.py daily --dir ./work    # 跑完当天全部确定性步骤，再输出提问
```

## 五、为什么提问比规则好

| | 规则 | 提问 |
|---|---|---|
| 模型的行为 | 机械匹配条目 | 真正推理 |
| 注意力 | 并列条目互相干扰，>20 条开始衰减 | 叙事有结构，天然抗稀释 |
| 遇到清单外的情况 | 不会处理 | 靠理解迁移 |
| 体积 | 越写越多 | 每个批次 3 个问题 |

规则告诉你"做什么"，提问让你自己想出"做什么"。
**前者在清单覆盖范围内有效，后者在清单外也有效。**

---

## 六、纪律

- 脚本输出的疑似项，未经人工复验不算漏洞
- 泛化推导出来的是**假设**，不是发现。验证不了就记 `[~]` + 排除理由
- `src_scout.py` 的 `--threads` 和 `--delay` 按平台限速规则调
- 只在授权资产范围内跑
